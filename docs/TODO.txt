(main quest)
Reduce number of circular dependencies in interfaces
- back when we didn't have incremental compilation, a bad habit formed when defining interfaces. 
  - we would define some interface, for example blockdev
  - there would be some hardware drivers that implement that interface, for example USB and AHCI
  - the problem was that it was convenient to let the interface know about its implementors
  - this results in there being a dependency from the interface to all of its implementors, 
    meaning that if we edit one implementor, then all implementors get recompiled. 
- ideally, interfaces should not know about their consumers or their implementors.
  - it's dumb to have to recompile the networking drivers when you made edits to USB for example. 
  - we are already doing a good job not letting interfaces know about consumers, we just have
    to clean up interfaces that know about their implementors. 
- interfaces to clean up:
  - blockdev
    - circular dependency between interface and implementors due to interface having dedicated 
      methods to create each implementor. 
  - vfs
    - was due to vfs init function also initializing ext2
  - idt
  - file 
  - tty
